# Troubleshooting

| Symptom                                                 | Check and fix                                                                                                                                                                  |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Nothing new appears after install                       | Expected: the SDK is headless. Place a host-owned surface and controls; enable approved components/sources.                                                                    |
| Discovered component is not enabled                     | Review `inspect`, approve its current digest or explicitly select it. Refresh keeps new candidates pending.                                                                    |
| Required callback/complex prop                          | Supply a wrapper with declared data inputs/events that calls existing host services. Do not cast away the requirement or infer callback behavior.                              |
| Source is incomplete                                    | Confirm semantics only if the entire authorized dataset is available. Otherwise use an explicit remote executor; never mark a cache complete.                                  |
| Approval digest changed                                 | Reinspect current source/config and review the new report; do not reuse an old digest.                                                                                         |
| Missing root or ambiguous routers                       | Place the provider manually under required host providers; select real navigation bindings. Vite gets automatic web setup first.                                               |
| COMPONENT_UNBOUND / SOURCE_UNBOUND / ACTION_UNBOUND     | Connect the reported stable capability ID through runtime bindings. Registration adds no fallback UI.                                                                          |
| SOURCE_DESCRIPTOR_MISMATCH                              | Adapter and client/server manifests must describe the same capability revision and fields. Refresh/deploy matching metadata.                                                   |
| DATA_CARDINALITY                                        | A single-record input received multiple rows. Add a reviewed selector/filter or use a many-record input.                                                                       |
| DATA_FAILED                                             | Inspect plan/type/nullability/source permissions, completeness, budgets and remote response shape. Use the hook's refresh/more commands with host feedback.                    |
| Actions do not execute                                  | Proposals are separate from execution. Supply host confirmation, permissions, arguments, a current revision/account, and an available handler. Preview/apply blocks execution. |
| Action timed out after dispatch                         | Do not automatically retry a mutation. Reconcile with the host service using its durable idempotency record.                                                                   |
| Saved changes rejected                                  | Reconcile capability revisions and stable IDs. Unsupported v1 shell/theme settings are reported; original v1 bytes remain recoverable.                                         |
| Generated file drift                                    | Preserve edits, move intended changes into config/overrides, then restore the tracked generated boundary before refresh/removal.                                               |
| Local section disappears or remounts during development | Keep keys stable; refresh static registration after structural edits. While stale, the wrapper shows the current host container. Check native geometry/device behavior.        |
| Web tries to load React Native                          | Import shared APIs from `@customitin/react`, DOM integration from `/dom`, and browser storage from `/storage`. Do not import the native example UI into a web-only app.        |

Inspect runtime codes and registration diagnostics in developer-owned tooling. Avoid exposing internal adapter errors, records, credentials or raw service responses to end users or the model. `doctor --typecheck` supplies static evidence only; test the host interaction and deployment separately.
