# Native testing

Expo apps use SDK 55 Expo Go. The iOS reference was exercised on a dedicated iPhone 17 Pro / iOS 26.5 simulator with Expo Go 55.0.34. Do not install a newer Expo Go runtime for a different SDK. Android uses Expo Go 55.0.7; the local Android API 35 emulator became unresponsive in System UI during testing, so interactive Android acceptance remains open. Both platforms' JavaScript/Hermes export results are tracked separately in verification.md.

```sh
npm run ios -w @customitin/recipe-example
npm run android -w @customitin/recipe-example
```

For the bare task app:

```sh
cd examples/task-app/ios
bundle install
bundle exec pod install
cd ..
npm run ios
# or, with Android SDK/JDK 17 and an emulator:
npm run android
```

The native project was generated by React Native CLI 20.0.0 against RN 0.83.10, then its CLI dependencies were patched to 20.2.0. The bare Babel config includes the export-namespace transform required by Zod. This repository does not contain a signed app-store binary. The optional web preview uses an Expo Metro/Babel branch; native builds use React Native's Metro/Babel configuration.

Native acceptance flow: open Customize; select an example; verify the original layout remains unchanged before apply; apply; open the new destination; open an existing detail; restart the app and confirm restoration; return to Customize and undo/reset. Repeat with a host account switch and an unavailable planner. Exercise VoiceOver/TalkBack, largest supported text size, keyboard access, contrast and reduced motion before release. The current rendering uses no animations.

A reusable Maestro flow is supplied at `tests/maestro/recipe.yaml`. Install a supported Maestro version in your environment, launch the matching Expo Go project, then run `maestro test tests/maestro/recipe.yaml`. It is a supplied test definition, not a claim that Maestro was installed or run during this implementation.
